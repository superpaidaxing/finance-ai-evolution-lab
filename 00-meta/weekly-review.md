## 本周建议主题与下周行动计划（2026 年第 45 周）

### 周期与主题

- 编制日期：2026-10-30；执行时间：2026-11-02（周一）至 2026-11-08（周日）。
- 建议主题：**银行管理驾驶舱：用生成式 AI 将模拟风险指标转为可核验的管理简报**。
- 核心问题：怎样让大模型解释已核验的指标变化，同时不算错数、不编造原因、不遗漏异常？
- 选择理由：对应路线图的“管理驾驶舱与经营分析”，将银行业务判断、数据口径、大模型摘要与风险治理串成一个小闭环，区别于近期已建议的反洗钱、信贷、上线评估与深度伪造主题。
- 当前状态：这是学习建议，不代表本周已经完成阅读或实验；也不推定此前 PR 中的计划已经执行。

### 学习边界与四层闭环

1. **概念层**：区分指标口径、数据质量、风险报告与生成式 AI 摘要；分清百分比变化与百分点变化。
2. **业务层**：只模拟“风险分析人员准备一页管理层周简报”，覆盖贷款余额、不良贷款余额及不良贷款率；不做客户画像、授信审批或自动经营决策。
3. **技术层**：采用“虚构汇总表 → 表格公式或 Python 确定性计算 → 人工核验 → 大模型生成带行号引用的文字 → 人工复核”的流程；暂不搭建驾驶舱系统、检索增强生成或智能体。
4. **治理层**：对指标追溯、口径一致、缺失值处理、无依据归因、人工签核和版本留痕设计检查项。

**安全红线**：仅使用公开报告和从零编造、明确标为“学习模拟”的汇总数据；不使用真实客户数据、脱敏客户样本、内部银行资料、生产系统截图、账号密钥或敏感信息。实验不接入银行系统；提示词、输出和日志均不得包含上述信息。

### 建议产出与验收标准

**最小必做：一份合并笔记即可**，建议保存为 `08-reading-notes/2026-w45-risk-dashboard-genai.md`，包含以下四部分；本次 PR 只追加计划，不预先创建笔记或宣称学习完成。

- [ ] 阅读摘记：3 个核心观点、2 条原文出处、1 个仍需验证的问题；对应“数据质量—文字可靠性—人工责任”。
- [ ] 一页用例卡：写清使用者、现有流程、痛点、输入输出、AI 边界、复核人和预期收益；目标仅为“辅助起草风险简报”。
- [ ] 一组学习模拟表与提示词草案：6 行数据（虚构分行甲、乙、丙 × 连续两周），至少含行号、周次、贷款余额、不良贷款余额、单位和数据版本；不良贷款率由公式计算，不由模型猜测。
- [ ] 一张核验清单：至少 5 项检查——数字可回溯、口径／单位一致、异常不遗漏、无依据不归因、人工签核及版本留痕；保留一条失败或待验证记录。

**有余力再做**：将用例拆入 `04-banking-use-cases/`，将实际实验记录拆入 `07-labs/`；不要求为了凑产出增加文件。

**轻实验规则**：先用表格公式或 Python 算出标准答案，再让大模型只根据已核验表写不超过 300 字的简报。计算口径：不良贷款率＝不良贷款余额÷贷款余额×100%；合计率用合计分子÷合计分母，不得直接平均各分行比率；环比变化区分金额、百分比与百分点，分母为零时标为不可计算。提示词要求每条数值结论标注来源行号，区分“事实／待验证解释／建议核查项”，资料不支持的原因必须写“无法从现有数据判断”。

**可选实验验收**：准备正常、缺失值、单位冲突 3 个小案例；后两者仅替换虚构数据，不混入真实样本。正常案例的引用和数值须与标准答案全部一致；异常案例须明确提示缺失／冲突，不补造数值或输出误导性合计；所有案例均不得凭指标变化编造因果。任一检查失败就记为未通过，修订提示词或退回人工处理，不以润色后的文字替代原始失败记录。没有合适的大模型工具时，只完成提示词和人工预期输出，并标“未运行”，不宣称验证通过。

### 忙碌时的保底与复盘问题

- 无法按标准版执行时，每个平日仅用 30 分钟推进同一笔记，周六跳过；若整周只能沉淀一次，就保留“3 个观点＋1 个用例＋1 条风险边界”，不另起工程项目。
- 周复盘只问：哪些数字可追溯？有哪些判断没有证据？哪一步必须由人负责？节省时间只是待测假设，没有实际计时就不写效率提升比例。
- 本周建议主题一句话：**先保证指标可信，再让 AI 帮忙表达；不让流畅文字掩盖数据问题。**
